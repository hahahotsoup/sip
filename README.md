## 你有没有遇到过这些

关注的博客更新了，但懒得一个个点开看；

作者偷偷改了一篇文章的结论，你却永远不知道——现实里，这就是被颠倒的黑白；

一口气加了十几个订阅，结果一天上百条，根本看不完，只能"全部已读"；

想让 AI 帮你查点东西，它却引用一堆你根本不信的营销号；

源里的东西看着挺厉害，但你就是读不进去；

你手头的 RSS 阅读器，用起来总有点笨拙。

要是中了任何一条，sip 大概能帮到你。

## 那试试看？

sip 是个**本地优先的个人信息库**：下载一个 exe，运行，加上几个订阅源，明天再回来看看。

Windows / macOS / Linux 都有单文件版。不用注册、不用云端，数据全在你自己电脑上一个叫 `readwithhotsoup` 的文件夹里——拷走就是迁移。

打开之后，随便点点、摸索一下就行。

> 🌐 **不想碰终端？试试网页版 sip-web**——一条命令起一个零依赖的**本地 Web 界面**：浏览器里订阅、阅读、搜索，样样顺手，不用碰命令行。[去看看 →](https://github.com/hahahotsoup/sip-webapiextra)

慢慢来，不着急。专治信息过载。

## 它能帮你做什么

sip 围绕五件事：**收集、保存、追踪、筛选、使用**——加订阅源与 OPML 导入、全文抓取与版本留档、`--diff` 盯住被改的稿子、跨源去重与今日哈汤、全文/语义搜索与 Agent 调用。完整功能与命令见 [功能总览](https://sip.hotsouprealm.top/参考/功能.html)，详细用法见 [Wiki](https://sip.hotsouprealm.top/)。

说到底，你拿到的是三样东西：**信息过载被治住、被悄悄改的事实藏不住、AI 不再引用你不信的来源。**

## 如果我实在玩不明白？

其实我设计的时候就想到了这个问题：sip 不止给人类用，也给 Agent 用。

我们做了 **Agent 调用能力**——Agent 能通过 CLI（配合 skill）调用 sip，能力与 TUI 近乎一致（除了 init，因为涉及 API Key）。人和 AI，都是一等公民——但**这扇门要你先开**：程序默认被拦，`sip --agentok`（真终端 + Web 密码）才是"允许 Agent 调用"的表示。见下面的安全声明。

## 它跟别的 RSS 阅读器不一样在哪

FreshRSS、Feedly、Inoreader 都挺好用——聚合订阅、展示文章，它们都做得很好，sip 不跟它们拼这个。

sip 想做的，是它们普遍没做、也不打算做的：**让信息可信、可追溯、可被 AI 使用。**

- 作者改稿、改结论？`--diff` 把变化轨迹留给你看，而不是让你永远看到旧版
- 想让 AI 查资料又怕它引用垃圾源？AI 只检索你订阅的源
- 信息过载刷不停？每天一小碗今日哈汤，读完就关

所以 sip 是本地单文件：作者改过文章悄悄留版本、五个源转发同一篇聚成一簇、报告把事实摆给你。而底层，它就做两件事——**确定性的规则**，和**本地事实的存储**。剩下的判断交给你；AI 只是默默帮你理解的助手，不替你决定信息的价值。

更完整的对照见 [Wiki · 竞品对比](https://sip.hotsouprealm.top/了解/竞品对比.html)。

## 一点产品哲学

说实话，市面上不缺"更聪明"的阅读器。sip 想做的不是比谁更聪明，而是把判断权还给你。

像《让子弹飞》里那句"我既要站着，还要把钱挣了"——sip 也有点这个意思：**我既要站着，还要把信息读了。** 不跪算法，不随大流，照样能读到自己在乎的东西。

信息本身没有好坏，"值不值得读"这件事，只有你说了算。AI 可以帮你把事实翻出来、把变化指出来，但"这个源对我还有没有价值"——那是你的决定。

所以 sip 坚持两件事：**确定性的规则**，和**本地事实的存储**。规则是你定的，事实是干净的，剩下的它不越界。

这也是为什么遥测默认是关的、AI 默认只是默默看着——它不是来替你活的。

## 至于怎么用

除了在界面里点，命令行也能玩：

    sip --today              # 今天读什么
    sip --search "RAG"       # 语义搜索（先手动跑 sip --init 配好 AI）
    sip --grep "量子纠缠"     # 全文搜索，不用 AI
    sip --diff 12 v1 v3      # 看一篇文章从 v1 到 v3 改了什么
    sip --insights           # 阅读报告，事实给你，决定你来做

对了，`sip --init` 要填 API Key，所以得你在真实终端里手动跑，脚本代跑是不行的。

## 想让 AI 只从你信任的源回答？

用 OpenClaw 或 Cherry Studio 把 sip 挂到群或机器人里，它只会用你订阅源里的内容回答。垃圾引用，再见。接入步骤见 [Wiki · Bot 接入](https://sip.hotsouprealm.top/使用/Bot.html)。

## 关于安全

sip 天生保守，因为它觉得信息首先是你的：

- 数据全在本地，不注册、不云端、不上传——拷走 `readwithhotsoup` 就是迁移（`backups/` 子目录可以不拷）
- 遥测默认关闭，只在你自己打开后才在本机记录，绝不自动上传，可随时清空/导出
- 全文抓取有 SSRF 防护：只抓 http/https，拒绝内网 / 回环 / 云元数据地址
- 数据库带完整性检查和 WAL，崩溃能自愈。**自愈只改名保留现场，永不删除你的库**；判定「损坏」还要求 SQLite 明确报错，光是「被占用/读不到」绝不算数
- **每天一份本地备份**：首次启动自动给数据库留快照（`readwithhotsoup/backups/`，保留 7 天，用 `VACUUM INTO` 保证一致）。误操作或自愈造成的问题可以直接回滚——`sip simon status` 能看到现有备份
- `--init` 只让你在真实终端手动跑——API Key 不进脚本、不进日志
- 搜索词等敏感记录只在本地，可 `telemetry export/clear` 随时清掉
- **孟思琳(simon)安全守护**：数据库损坏自动修复、SSRF/终端注入防护——默认开启、无法关闭、只能调节挡位（`sip simon status`）。挡位 2 起 CLI 写操作一律拒绝，挡位 3 起 CLI 全部拒绝（`simon status` 与 `simon level` 除外）
- **升档（收紧保护）任意通道放行**：Agent 发现异常时要能立刻收紧，收紧不需要授权
- **降档（放宽保护）走人工通道**：真交互终端 + Web 密码。管道、脚本、`--json` 一律拒绝；连续 5 次口令错误锁 15 分钟。没设 Web 密码时退化为逐字短语（更弱，界面会明说）
  - 强度诚实说明：挡得住**被脚本/Agent 包装的调用**；挡不住**已经以你的身份运行、且知道口令的程序**——那需要独立用户账户。**这是应用层门，不是权限边界**
- **Agent 外部调用默认关闭**：程序（脚本、Agent、管道）读不了你的库，只有你自己的终端不受影响。开启用 `sip --agentok`（真终端 + Web 密码）；关闭 `sip --agentoff`（收紧，任意通道）；查看 `sip --agentstatus`（也显示在 `sip simon status` 里）  - 这是**和挡位独立的另一条轴**：挡位是命令级策略（读/写/全部），会连你自己的终端一起拦；Agent 门是调用者级策略（人/程序），只拦非交互调用
  - 开关只存**系统凭据库**（改 `sip_settings.json` 绕不过去），**没有兜底文件**。曾有过 `agent_mode.json` 兜底，但它的实际触发条件是「凭据库还没有值」——**那正是全新安装的默认状态**，等于任何程序写个 JSON 就能把这道门打开。凭据库读不到值 = 关（fail closed）；凭据库真坏了时人照样能用 CLI/TUI，丢的只是「程序可以调用 sip」这一项授权，属于收紧方向的失败，就该响亮地失败
  - ⚠️ 副作用：`sip -l | grep x` 这种自己也接了管道的用法会被算作程序调用
- 🔍 **凭据库写满会让安全设置静默失效**（已定位并修复过一次）：`CredWrite` / `cmdkey` 报 `ERROR_NOT_ENOUGH_MEMORY`（**错误 8**）时，**挡位改不动、AI Key 存不进、Agent 门开不了**——都只表现为"改不动"，不报任何错。原因是**条目数量触顶**（实测 842 条时开始失败），与凭据内容大小无关。Web 登录会话现在不再往凭据库写东西（密钥只在内存里，见下），受影响的只剩挡位 / AI Key / Agent 门
  - 排查：`cmdkey /generic:sip_probe /user:x /pass:y` —— **错误 8 = 存储满，错误 5 = 权限**，两者症状相同但修法完全不同；写完记得 `cmdkey /delete:sip_probe`
  - 清理：`cmdkey /list` 看条目，`cmdkey /delete:<完整 target>` 删。本机曾因测试泄漏堆积 **746 条垃圾（占整个凭据库 88%）**，删掉后写入立刻恢复
- 🧼 **正文只在服务端净化后才发给页面**：标签白名单 + 属性白名单（黑名单永远漏——`on*` 一大串、新标签层出不穷），`script`/`iframe`/`svg`/`form`/`style` 等**连内容一起丢**，URL 只放行绝对地址，接口也只返回净化后的 `bodyHtml`。**订阅源作者写一篇文章，不能变成在你机器上运行的脚本**
- 🌐 **网页版怎么打开**：`sip --start` 会打印一行 `Web UI : http://…/?t=…`，**用那条链接打开**。
  - 无密码模式下裸访问 `/` 会被故意拒绝（只给一张说明页）——否则本机任何程序 GET 一次就能拿走你的库。令牌只存在于终端输出里，且换到 cookie 后立刻从地址栏消失
  - 不想每次复制链接？`sip webpass` 设个密码，之后直接开页面登录
  - 🔑 **登录一次管到重启**：会话是**进程内的一次性密钥**，一个浏览器一把，且**只活在这次运行里**。
    - 同一个浏览器：登录成功后一路免密码（刷新、重开浏览器都算），直到 `sip --start` 退出
    - **换浏览器要重新登录**（无密码模式则要重新打开终端里那条新链接）：钥匙是按浏览器签发并绑浏览器指纹的，抄走 cookie 值也没用（指纹取 User-Agent，浏览器大版本更新后可能要重登一次）
    - **重启 sip 后所有人重新登录**：会话表只在内存里，进程一退就没了。登录页会明说「sip 重启过了」，不用猜为什么又弹密码框
  - **让手机/平板访问**：Windows 上非管理员绑局域网地址会报「拒绝访问」（http.sys 需要 URL 保留）。按提示在管理员命令行跑一次 `netsh http add urlacl url=http://<你的IP>:8777/ user=Everyone`，或直接以管理员运行 `sip --start`。绑 `127.0.0.1` 两者都不需要
    - 手机/平板是另一个浏览器 = 另一把钥匙，首次访问照样要登录（或重新复制链接）

一句话：它不收集、不追踪、不偷偷上传你的东西。

## 源码结构（哪个文件是什么）

**一个文件 = 一件事**。想改哪块，直接开对应的文件：

| 文件 | 是什么 |
|---|---|
| `sipcore.cs` | **核心**：库结构与迁移、抓取入库、FTS/语义检索、今日哈汤、跨源去重、源规则、阅读报告、AI 配置与密钥，以及 CLI 命令分发（入口的顶层语句也在这里） |
| `Tui.cs` | 终端界面（无参数启动的那个 TUI） |
| `Web.cs` | **Web 的全部服务端**：进程内 HTTP 服务、路由与各接口处理器、正文净化、网页登录（口令 / 会话 cookie / 无密码模式的引导令牌）、`sip webpass` 与首次向导 |
| `web/` | 前端资源：`index.html`、`login.html`、`login-bg.png`（编译时作为 EmbeddedResource 内嵌进 exe，**改前端要重新构建**） |
| `simon.cs` | 孟思琳安全守护：挡位、**人工通道**（真 TTY + 口令、失败锁定）、Agent 门 |
| `Sumenia.cs` | 遥测（默认关闭，只写本机） |
| `SipMarkdown.cs` | Markdown 渲染（TUI 用） |
| `ImageSixel.cs` | 终端图片（Sixel 协议） |
| `languages/*.json` | 译文。键就是英文原文，`Lang.T("...")` 按它查表——**所以改英文原文等于换键**，译文会静默变孤儿 |
| `tests/Sip.Tests/` | 进程级黑盒测试：真起 `sip.exe`、真发 HTTP，每个用例一个隔离数据目录。数量见 [测试报告](https://sip.hotsouprealm.top/测试报告.html) |
| `docs/` | 业务逻辑梳理、Web 界面评审、用户快速手册 |

> 为什么都是 `partial class Program`：入口用的是顶层语句，编译器生成的类就叫 `Program`，其他文件只能以 partial 形式共享作用域。好处是内部方法随手可调（Web 层直接调 CLI 用的同一个函数），代价是没有封装边界——**所以靠文件名表达归属**，一个文件只放一件事。
