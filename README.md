## 你有没有遇到过这些

关注的博客更新了，但懒得一个个点开看；

作者偷偷改了一篇文章的结论，你却永远不知道——现实里，这就是被颠倒的黑白；

一口气加了十几个订阅，结果一天上百条，根本看不完，只能"全部已读"；

想让 AI 帮你查点东西，它却引用一堆你根本不信的营销号；

源里的东西看着挺厉害，但你就是读不进去；

想多方面查证一件事，却被海量信息淹没；

你手头的 RSS 阅读器，用起来总有点笨拙。

要是中了任何一条，sip 大概能帮到你。

## 那试试看？

sip 是个**本地优先的个人信息库**：下载一个 exe，运行，加上几个订阅源，明天再回来看看。

Windows / macOS / Linux 都有单文件版。不用注册、不用云端，数据全在你自己电脑上一个叫 `readwithhotsoup` 的文件夹里——拷走就是迁移。

打开之后，随便点点、摸索一下就行。

慢慢来，不着急。专治信息过载。

## 它能帮你做什么

sip 围绕五件事：**收集、保存、追踪、筛选、使用**——加订阅源与 OPML 导入、全文抓取与版本留档、`--diff` 盯住被改的稿子、跨源去重与今日哈汤、全文/语义搜索与 Agent 调用。完整功能与命令见 [功能总览](https://sip.hotsouprealm.top/参考/功能.html)，详细用法见 [Wiki](https://sip.hotsouprealm.top/)。

说到底，你拿到的是三样东西：**信息过载被治住、被悄悄改的事实藏不住、AI 不再引用你不信的来源。**

## 如果我实在玩不明白？

其实我设计的时候就想到了这个问题：sip 不止给人类用，也给 Agent 用。

我们做了 **Agent 调用能力**——任何 Agent 都能通过 CLI（配合 skill）调用 sip，能力与 TUI 近乎一致（除了 init，因为涉及 API Key）。人和 AI，都是一等公民。

## 它跟别的 RSS 阅读器不一样在哪

FreshRSS、Feedly、Inoreader 都挺好用——聚合订阅、展示文章，它们都做得很好，sip 不跟它们拼这个。

sip 想做的，是它们普遍没做、也不打算做的：**让信息可信、可追溯、可被 AI 使用。**

- 作者改稿、改结论？`--diff` 把变化轨迹留给你看，而不是让你永远看到旧版
- 想让 AI 查资料又怕它引用垃圾源？AI 只检索你订阅的源
- 信息过载刷不停？每天一小碗今日哈汤，读完就关

所以 sip 是本地单文件：作者改过文章悄悄留版本、五个源转发同一篇聚成一簇、报告把事实摆给你。而底层，它就做两件事——**确定性的规则**，和**本地事实的存储**。剩下的判断交给你；AI 只是默默帮你理解的助手，不替你决定信息的价值。

更完整的对照见 [Wiki · 竞品对比](https://sip.hotsouprealm.top/了解/竞品对比.html)。

## 一点产品哲学

说实话，市面上不缺"更聪明"的阅读器。sip 想做的不是比谁更聪明，而是把判断权还给你。

像《让子弹飞》里那句"我既要站着，还要把钱挣了"——sip 也有点这个意思：**我既要站着，还要把信息读了。** 不跪算法，不随大流，照样能读到自己在乎的东西。

信息本身没有好坏，"值不值得读"这件事，只有你说了算。AI 可以帮你把事实翻出来、把变化指出来，但"这个源对我还有没有价值"——那是你的决定。

所以 sip 坚持两件事：**确定性的规则**，和**本地事实的存储**。规则是你定的，事实是干净的，剩下的它不越界。

这也是为什么遥测默认是关的、AI 默认只是默默看着——它不是来替你活的。

## 至于怎么用

除了在界面里点，命令行也能玩：

    sip --today              # 今天读什么
    sip --search "RAG"       # 语义搜索（先手动跑 sip --init 配好 AI）
    sip --grep "量子纠缠"     # 全文搜索，不用 AI
    sip --diff 12 v1 v3      # 看一篇文章从 v1 到 v3 改了什么
    sip --insights           # 阅读报告，事实给你，决定你来做

对了，`sip --init` 要填 API Key，所以得你在真实终端里手动跑，脚本代跑是不行的。

## 想让 AI 只从你信任的源回答？

用 OpenClaw 或 Cherry Studio 把 sip 挂到群或机器人里，它只会用你订阅源里的内容回答。垃圾引用，再见。接入步骤见 [Wiki · Bot 接入](https://sip.hotsouprealm.top/使用/Bot.html)。

## 关于安全

sip 天生保守，因为它觉得信息首先是你的：

- 数据全在本地，不注册、不云端、不上传——拷走 `readwithhotsoup` 就是迁移
- 遥测默认关闭，只在你自己打开后才在本机记录，绝不自动上传，可随时清空/导出
- 全文抓取有 SSRF 防护：只抓 http/https，拒绝内网 / 回环 / 云元数据地址
- 数据库带完整性检查和 WAL，就算崩溃也能自愈，不丢数据
- `--init` 只让你在真实终端手动跑——API Key 不进脚本、不进日志
- 搜索词等敏感记录只在本地，可 `telemetry export/clear` 随时清掉
- **孟思琳(simon)安全守护**：数据库损坏自动修复、SSRF/终端注入防护、非交互调用管控——默认开启、无法关闭、只能调节挡位（`sip simon status`，降挡只能在 TUI 命令栏）。挡位 3 可对整个数据文件加密（SQLCipher + AES），密钥自动生成、只存系统凭据库，其他软件读不到你的数据；换机迁移用 `sip simon export-key`

一句话：它不收集、不追踪、不偷偷上传你的东西。

## 最近在折腾什么

- ⚡ **百万级适配**：100 万篇文章的库实测——`--grep` 全文搜索 2.2 秒 → 0.5 秒（FTS5 索引，中文子串可搜），TUI 秒开（侧栏懒加载），`--today` 7.5 秒 → 3 秒，大源更新一次事务提交

## 名字与口号

### 🍲 sip ——「品，你细品。」

- **出处**：`README.md` 开头、TUI 启动界面、本站首页 tagline
- **释义**：`sip` 英文本义就是**小口啜饮**。程序的整个气质都在这两个字里：信息像汤一样，小口喝、慢慢品，不贪多、不着急——「专治信息过载」。TUI 启动时那一句「品，你细品。」，既是口号，也是使用说明。
- **例句**：

> ——「品，你细品。」

> 慢慢来，不着急。专治信息过载。

### 🍵 今日哈汤（Today's Hotsoup）

- **出处**：`README.md`、`Tui.cs`（今日哈汤阅读界面）、`sip --today`
- **释义**：每日推荐阅读清单，默认一天五篇，规则式选文、附理由与预估时长，**一天固定一碗**。「哈」读 hā，是**胶东半岛（威海、青岛一带）及东北部分地区的方言读法，即「喝」**——威海、乳山一带土话里，「喝汤」就说「哈汤」[^1]。所以「今日哈汤」=「今天喝汤」：把读文章说成喝汤，把信息过载治成一日三餐。
- **例句**：

> 每天一小碗今日哈汤，不贪多。

> 信息过载刷不停？每天一小碗今日哈汤，读完就关。

> （今日哈汤已生成于 {0} · --refresh 可重新来一碗 · 新文章随时可从侧栏/--search/--grep 看）

- **深度梗**：今日哈汤的界面标题是「今日哈汤 · {日期} · 第 {批} 批 · 已完成 {n}/{m}」——把阅读进度做成了"喝到第几碗"。而"重新生成"被说成「重新来一碗」，喝汤的仪式感拉满。

[^1]: 出处考证：[乳山方言四六级【饮食】](https://www.sohu.com/a/387442625_677254)、[山东威海土话](http://www.360doc.com/content/23/0608/14/7201102_1083951975.shtml)、[老威海话（二）](https://tiebac.baidu.com/p/994209471)。东北话里「哈啤酒」也是同一读法。

### 📁 readwithhotsoup

- **出处**：`README.md`、[概念：数据目录](https://sip.hotsouprealm.top/了解/概念.html)
- **释义**：sip 的所有数据（数据库、全文缓存、阅读进度、遥测）都放在这个文件夹里。文件夹名字面意思是「和热汤一起读」——连数据目录都要泡在汤里。它是"汤宇宙"的基础设施：**拷走就是迁移**，不需要账号、不需要云端。
- **例句**：

> 数据全在你自己电脑上一个叫 `readwithhotsoup` 的文件夹里——拷走就是迁移。

## 角色档案

sip 把两个底层子系统拟人成了两位女孩。官方设定：**她们是表姐妹**。性格对照鲜明——一个默认不在、来去自由，一个永远在岗、无法关闭。

### 💧 苏暖泉（Sumenia）——遥测萌妹纸

- **出处**：`Sumenia.cs`、`sip telemetry`、[遥测与隐私](https://sip.hotsouprealm.top/参考/遥测.html)
- **释义**：本地阅读遥测服务的拟人化。她"会主动了解你的阅读习惯"——记录哪些文章被打开 / 读完 / 跳过、AI 调用与搜索情况，数据只存本地 `telemetry.db`，绝不上传。她的存在哲学是：**默认不在**，你开启她才出现；不开，她就不存在。
- **例句**：

> 一个默认不在的萌妹纸，只在你把她招来之后，才在本地悄悄记你的阅读习惯——你不开，她就不存在。

> 苏暖泉来啦（仅本地记录，不会上传）

> 苏暖泉已离开（历史数据保留，不再记录新事件）

- **深度梗**：表姐妹设定中，苏暖泉是"招之即来"的那位；她与孟思琳（见下）同为程序的拟人角色，却一个代表"可选的温柔"，一个代表"不可关的守护"。~~（简而言之：一个负责记笔记，一个负责看门。）~~

### 🔒 孟思琳（simon）——永远在岗的安全守护

- **出处**：`RssReader.cs`（孟思琳(simon) 安全守护）、`Tui.cs`、`sip simon status|level|export-key|import-key`
- **释义**：安全子系统的拟人化，负责数据库自愈、SSRF 防护、终端注入拦截、非交互调用管控、**数据加密**（挡位 3：rss.db 用 SQLCipher、全文缓存与 dedup 规则用 AES-GCM，密钥自动生成只存系统凭据库，连她自己都不许你把密钥记在纸上）。与苏暖泉相反，她**默认开启、无法关闭，只能调节挡位**（1=基础 / 2=严格 / 3=极致），是"此软件的最后一道安全防线"。连降挡都**只能在 TUI 命令栏当面操作**——她不信任脚本，也不信任命令行。
- **例句**：

> 🔒 孟思琳(simon) 则永远在岗：数据库自愈、SSRF 防护、终端注入拦截、非交互调用管控——默认开启且无法关闭，只能调节挡位。永远作为此软件的最后一道安全防线。
