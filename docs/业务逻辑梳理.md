## 1. 总览：一个进程，三种入口

`sip` 是单进程程序，同一套核心函数被三个入口共用：

| 入口 | 触发方式 | 位置 |
|---|---|---|
| CLI | 任意带参数调用 | `RunCli` 3052 |
| TUI | **无参数**（或 `sip pic`） | `RunTui`（`Tui.cs`） |
| Web | `sip --start`（阻塞） | `StartWebServer`（`WebServer.cs:18`） |

启动链路（Main 顶层语句 41–99）：

```
建 dataDir(43) → 语言复制/合并(46) → InitDatabase(49)
   └─ CheckMainDbIntegrity(4130) → PRAGMA FK+WAL(4139) → 建表建索引(4144)
      → 六条 ALTER 迁移(4229)
→ 选项解析(55) → Lang.Init(69) → TelemetryService.Init(70)
→ BackupDbDaily(74)
→ args>0 ? RunCli : (真终端 ? StartWebFromCli(无参数=Web，v2.0.0 起) : PrintHelp+退出1)
→ TelemetryService.Shutdown → MarkCleanExit
```

**只有两处会阻断启动**：`.db-encrypted` 遗留标记 → `Environment.Exit(1)`（4369-4381）；建表语句抛异常（4226 无 try/catch）。
完整性检查、备份、遥测**全部吞异常**，不阻断启动。

## 2. 跨域契约（先看这节）

### 2.1 编号双轨：订阅源用「显示编号」，文章用「真实 Id」

`GetRealId(displayNum)` 5622 的 SQL **只查 `Feeds` 表**，全项目 14 个调用点无一指向文章：

```
1312 FeedInfoCli · 2799 PolicyCli · 3156 -l <N> · 3908 UpdateFeed · 3964 SetFeedSchedule
4011 SyncCli --feed · 5076 ExportCli feed:N · 5642 DeleteFeed · 5692 AddTimestamp
5726 RemoveTimestamp · 6408 IndexArticlesCli · 6534 SearchCli --feed · 6624 GrepCli --feed · 7215 SummaryCli
```

而文章的入口**直接拿真实 Id**：

```csharp
int.TryParse(args[1], out int sNum)     // 3100
ShowArticleJson(sNum, ...)              // 3108
ArticleExists(sNum, ...)                // 3111
```

**后果**：用户看到列表印着 `[1/37]`，敲 `sip --show 1` **不会报错**，会拿到 Id=1 的那篇（完全另一篇）。文章列表不得不印一句警告来兜：

```
[序号/真实ID] 左边=列表序号，右边=文章全局真实 ID（--show/--versions/--summary 用右边的 ID）
```

Web API 一律用真实 Id（`/api/feeds/{realId}`、`/api/articles/{realId}`），前端也用 `f.id` / `a.itemId`——三端只有 CLI 的文章命令用真实 Id，其余用显示编号。

### 2.2 侧挂文件：11 个 JSON 全是「整份读 → 改 → 整份写」，且无锁

`Path.Combine(dataDir, ...)` 共 24 处。其中以 JSON 持久化的：

`article_signals` · `reading_progress` · `feed_health` · `sip_today_cache` · `dedup` · `source_policy` · `sip_settings` · `simon_events` · `web_auth` · `fulltext/vecs.json` · `telemetry_consent`

**全项目的 `lock` 只出现在三处**，且都与这批文件无关：

- `Sumenia.cs:231,260` —— telemetry 缓冲
- `Tui.cs:736` —— 某个对话框的 StringBuilder
- `tests/Sip.Tests/TestHost.cs:130` —— 测试用模板锁

**`WebServer.cs:12` 的 `WebWriteGate` 声明了，但全项目再没被引用过。**

而 Web 是**每请求一线程**：

```csharp
_ = Task.Run(() => HandleWebContext(ctx));     // WebServer.cs:72
```

配合 TUI 同进程写同一批文件 → **手机和 PC 同时点赞就是后写覆盖先写**。丢写是静默的（所有 `SaveX` 都 `catch { }`），命令仍然报成功。

### 2.3 挡位检查被实现了三遍，而且三份不一致

`WebServer.cs:233-254` 的注释写着：

```csharp
// 与 CLI 同一语义：挡位≥2 拦破坏性写，挡位≥3 拦一切写
bool destructive = what is "delete" or "sync" or "update" or "update-all" or "add";
```

但 CLI 在挡位 2 下拦的是**一切非只读命令**（`!SimonIsReadOnly(cmd, sub)`，`simon.cs:121`）。两边的集合并不相同：

| 操作 | 挡位 2 下 CLI | 挡位 2 下 Web |
|---|---|---|
| `--like` / `POST /api/articles/{id}/like` | **拒绝** | **放行** |
| `--fulltext` / `/fulltext` | **拒绝** | **放行** |
| `--summary` / `/summary` | **拒绝** | **放行** |
| 归档 / `/archive`、`/unarchive` | **拒绝** | **放行** |

**同一个操作，因为走哪个通道而裁决相反**，而注释声称语义相同。

另外 TUI 命令栏**完全绕过**这套检查（`simon.cs:108` 的设计声明："TUI 命令栏不经此检查，永远是真人通道"）。所以实际是三套并行的策略。

### 2.4 删源清理缺口：清了 8 处，漏了 6 处

`DeleteFeedByRealId` 3837（Web/部分 CLI 走的正确实现）清理了：

`fulltext/*.md`(3852) · `fulltext/vecs.json`(3855) · `Vectors`(3860) · `VectorsChunks`(3863) · `ItemsFts`(3865) · `Items`(3867) · `Feeds`(3876) · `dedup.json`(3881)

**没清理**：`article_signals.json` · `reading_progress.json` · `sip_today_cache.json` · `source_policy.json` · `feed_health.json` · `imported/` 下的文件与 asset 目录

**用户可见的症状**（CLI `LikesCli` 1560 与 Web `HandleLikes` 都不过滤查不到标题的条目）：

```
$ sip --likes
[42] ♥            ← 心还在，标题空了（源/文章已被删）
```

**这也解释了数据目录里的孤儿文件**：`imported/` 有 6 个文件，而「本地导入」源只有 2 条——删源时文件不跟着走。

好消息：`Items.Id` 是 `AUTOINCREMENT`，Id 不会重用，**孤儿条目不会被错误归属到新文章**上，只是永久堆积。

**更严重的一处**：CLI 删源走的是另一份实现 `DeleteFeed` 5640 / 5671-5681，它**连 `DELETE FROM ItemsFts` 都没有** → FTS 孤儿行。

### 2.5 错误与退出码契约（Agent 接口）

```
0 = 成功
1 = 通用错误（参数/用法/数据库）
2 = 网络/服务不可达
3 = 资源未就绪（AI 未配置 / 密钥缺失 / 无索引 / 找不到）

JSON: { success: true,  data: … }
      { success: false, error: { code, message, suggestion, details } }
```

`SetExit` 6032 用 `Math.Max` 取「最严重」。**问题**：`ExitCodeFor` 6022 把 `3（未就绪）` 排在 `2（网络错误）` 之上，所以一次同时撞上网络错误和「找不到」的调用会报 3——**网络故障被「资源不存在」盖掉**，Agent 会据此误判成配置问题。

### 3.3 完整性与自愈

`CheckMainDbIntegrity` 4361（整体 try 吞异常 4423）决策树：

1. `.db-encrypted` 存在 → 打印 6 行提示 → `Exit(1)`，**文件不动**（4369-4381）
2. `rss.db` 不存在 → return 4382
3. **`.clean-exit` 存在 → 删标记 → return，跳过 quick_check** 4384-4388
4. stderr 提示「检查中」
5. `QuickCheckHealth` 4438（busy_timeout=2000，最多 3 次）：
   - **Ok**（`quick_check == "ok"`）→ 写 `.clean-exit` → return 4392
   - **Unavailable**（非 11/26 的 SqliteException、其它异常、或全 busy）→ 打印「占用/读不到，未改动」→ return 4397
   - **Corrupt**（`rc ∈ {11 SQLITE_CORRUPT, 26 NOTADB}` 或 3 次拿到非 ok 结果）→ 下一步
6. `ClearAllPools` → `File.Move(rss.db → rss.db.corrupt-<ts>)` 4406；**失败 → 打印「无法隔离，保持原样」return** 4416；成功 → `SimonRecord("repair_db")` 4420 → 由 `InitDatabase` 建**全新空库**（无数据恢复）

**`rss.db` 在任何路径下都不会被删除**（全仓 `File.Delete` 仅 631/1172/3853/4386/4483/4498/6482/7082 与 `WebAuth.cs:95/232`，无一指向 `dbPath`；唯一「移除」是改名 4410）。

⚠️ **`.clean-exit` 的语义是「上次进程正常退出」，不是「库现在没坏」**：全检只在异常退出后发生，正常退出后带病库**永不再检**（第 3 步早退）。

### 3.4 备份

触发：每次启动一次（74，CLI/TUI/Web 通用），靠文件名去重（4479）。前置：`rss.db` 存在 4475、当日目标不存在 4479。

顺序：判定 target → `tmp = target + ".tmp"` → 删残留 tmp 4483 → `VACUUM INTO @tmp`（参数绑定 4489）→ `File.Move(tmp, target, overwrite: true)` 4493 → `PruneBackups`。
失败：删 tmp + stderr 一行 4496-4500。

保留算法 4505-4521：按文件名降序 → 删除 index ≥ 7（**留最近 7 份**）→ 重新枚举 → `total = ΣLength` → 从最旧往上删，条件 `total > 2GiB && i > 0` → **至少留 1 份**（最新那份即使 >2GiB 也保留）。

### 3.5 遥测（Sumenia）与主库的关系

**完全隔离**：独立 `telemetry.db` / consent / checkpoint（`Sumenia.cs:31-33`），独立连接，**绝不动 `rss.db`**（117）。

### 4.2 `DownloadAndSaveToDb` 全流程（5391）

1. 5395 规范化 URL（无 scheme 补 `https`，记 `wasAutoPrefixed`）
2. 5403 30s 超时 + 固定 Chrome UA；**仅当是自动补的 https 且遇 `HttpRequestException`** 才降级 `http://` 重试一次（5412-5419）
3. 5422 解析 feed
4. 5425 开库，**5430 `BeginTransaction`**
5. 5434 `GetActiveRawXml`（`Title=@t OR Title LIKE @t||'\_%' ESCAPE '\'` 再按 `IsArchived` 过滤）：命中 → `ShowFeedXmlDiff`；**有变才** `UPDATE Feeds SET RawXml, LastFetched` 5449；`feedId` 由标题回查 5464。未命中 → `INSERT INTO Feeds` 5474
6. 5496 **无条件**刷新 `LastCheckedAt = now`（内容没变也刷）
7. 5504 `ShowDiff`
8. 5505 `Commit`
9. 5510 `MaybeIndexNewArticles`（**事务外**另开连接）

**事务边界 5430–5505**，涵盖 `Feeds`/`Items`/`ItemsFts`；**不涵盖**网络、telemetry、`feed_health.json`、向量化。

### 4.3 版本判定 `ShowDiff`（5798）

```
Guid = item.Id ?? item.Link ?? ""          5805
新源 → 不查重、不查 dedup，直接 version:1   5807
旧源 → SELECT Id, Version, Title, Content
        FROM Items WHERE Guid = @guid AND Status = 'active'     5817
  ├ 命中且 oldContent == item.Content → 跳过（5833）
  ├ 不等 → 该 Guid 下全部 active 置 archived + ArchivedAt（5838）
  │        再插 Version = oldVersion + 1（5847）
  └ 未命中 → DedupImportBlocked（5856）后 version:1
```

**排序：改稿判定只比较 `Content`，无阈值——任一字节差异即新版本**（标题/摘要改动不触发）。

`InsertNewItem` 5771：`INSERT Items`（固定 `Status='active'`）→ `last_insert_rowid` → `SyncFtsInsert` 4328（异常静默）。

### 4.4 ⚠️ 修正：`Status='deleted'` 是**死值**

**全代码库没有任何写入 `Status='deleted'` 的地方**（已 grep 确认，5 处引用全是 `COUNT(*)` 与标签映射：`sipcore.cs:4929/5131`、`Tui.cs:497/610`、`WebServer.cs:461`）。

因此：

| 宣称 | 实际 |
|---|---|
| 「作者删稿 → 标记 `deleted`，内容保留」 | ❌ **未实现**。`ShowDiff` 明确不做删除检测（5870-5871） |
| UI 标签「{0} deleted by author, but archived for you」（5051） | ❌ 永远不触发，`DeleteCount` 恒为 0 |
| 作者**改**稿 → 旧版留档 + diff | ✅ **已实现且工作**（5833-5847） |

**「改稿追踪」是真的，「删稿追踪」是空的。** README 里「作者偷偷改了一篇文章的结论，你却永远不知道」成立；但「作者删了文章你也能看到」目前不成立。

### 4.5 不变量

1. `Feeds.Title` **无唯一约束**（4145），同名多行合法；「活动源」= 标题不匹配 `_\d{8}_\d{6}$`（5612）
2. 归档 = 标题加 `_yyyyMMdd_HHmmss`（5712）；已归档不可再归档（5705）；去归档须无同名（5748）
3. 归档源不抓取、不比对（3922/4105/5315/5605）
4. `(Guid, Status='active')` **期望唯一但无唯一索引**（仅有普通 `idx_items_guid` 4212）
5. `Version` 单调 +1
6. `Status` 实际取值：`active` / `archived` / `dedup`（2316）；`deleted` 为死值
7. 下载成功即刷新 `LastCheckedAt`（5496），即使内容未变
8. diff 异常 → 返回 false，不覆盖 `RawXml`（5919）
9. 内容相同时 Title/Link/Description **不更新**

### 4.6 调度

语法全集：`^\d+[mhd]$` 5213（**无秒、无 `s`、不可组合**）· `daily@HH:mm` 5221 · `weekly@Ddd HH:mm`（缩写或全称）· 空 / `manual` 5209 · 其余 null

`ComputeNextDue` 5267：`manual` → null；Interval → `lastChecked + iv`；daily → 今日 HH:mm，若 `<= lastChecked` 则 +1d；weekly → 以 now 定位当周目标星期 HH:mm（`(target - now.DayOfWeek + 7) % 7`），若 `<= lastChecked` 再 +7d

`IsFeedDue` 5289：解析失败/manual → false；**`lastChecked` 为空 → true（首次即到期）**；否则 `now >= due`

时间基准全为 `DateTime.Now` **本地时间**；写入 `"O"` 无 Kind（5454/5482），读回 `RoundtripKind`（5322）→ **跨时区迁移会漂移**。

### 4.7 可疑点

1. **5819/5840 缺 `FeedId` 条件（最严重）**：Guid 为 `""` 时（`item.Id` 与 `item.Link` 皆空）**跨源误归档他源文章**；多源共用 Guid（转载、`local://import` 1145）同样互踩。已核实 SQL 确实无 `FeedId`。
2. `Status='deleted'` 死值（见 4.4）
3. **两级 diff 判据不一致**：Feed 级摘要用 `[id] Title`（5927），Item 级只比 `Content`（5833）→ 会出现「源已更新但无新版本」或「有新版本但 RawXml 未更新」
4. **5216 `int.Parse` 无保护**：`--schedule 1 99999999999m` 抛 `OverflowException`，`SetFeedSchedule` 无 catch
5. 5464 回查 feedId **无归档过滤、无 ORDER BY**：同名活动+归档并存时取行不确定
6. 5449 不更新 `FeedUrl`：5418 的 http 回退结果对已存在源失效
7. **重复实现且行为分叉**：`AddTimestamp`/`RemoveTimestamp`/`DeleteFeed`（5690/5724/5640）与 `*ForRealId`（3799/3816/3837）两套；`DeleteFeed` 5672-5681 **不删 `ItemsFts`**，`DeleteFeedByRealId` 3865 删 → CLI `-X` 路径留孤儿 FTS 行
8. **静默失败**：`LoadFeedHealth`/`SaveFeedHealth` 全 catch（1226/1237）；`RefreshOneFeed` 吞异常（7061）**且不记失败** → 健康状态失真
9. **并发**：TUI 用 `.Wait()` 阻塞（`Tui.cs:709/776/2287`）；无唯一约束下 `GetActiveRawXml → INSERT Feeds` 是 **TOCTOU**，可产生同名重复源（未确认）
10. 5380 `"in " + UntilText` 在 <60s 时输出英文「in soon」

### 5.1 渲染链路 `BuildArticleMarkdown` 3470

顺序：`# 标题`（`EscapeMd∘CjkSpace` 3493）→ 空行 → `**作者** · **日期**`（仅非空 3497）→ `**来源**: [feedTitle|link](…)` 3501 → `---` → 正文：

- **contentMode=true** 3508：`Content` 空则 `Description`，经 `HtmlToMarkdown(wrapWidth, link)`；若 `fulltext/<id>.md` 有缓存 3513 → `## Fetched full text` + `EscapeMd(全文，整段不截断)`；无缓存且 `showFetchHint` 且内容短 → `> 摘要过短…` 提示
- **contentMode=false** 3531：`## AI Summary` + `EscapeMd(Summary)`；否则 `HtmlToMarkdown(desc)`，desc 空 → `(No summary…)`

末尾统一 `StripControlChars(md)` 3550。「短」= 选中正文 Trim 后 **<100 字符**（288/4641）；「长」= **无任何上限**。

`WalkHtml` 3594 标签映射：`h1-h6`→`#`×n · `p/div/section/article/blockquote`→空行 · `br`→`\n` · `hr`→`---` · `b/strong`→`**` · `i/em`→`*` · `del/s/strike`→`~~` · `u`→`__` · `code`→反引号 · `pre`→围栏 · `a`→`[文本](href)` 并登记 `TuiMdState.Links` · `img`→`![ZWSP](url)`（baseUrl 解析相对路径）· `ul/ol`→`listDepth*2` 缩进的 `- `（**ol 不编号**）· `tr`→换行 · `td/th`→`文本 | `
**丢弃**：`script/style/head/nav/footer/aside` 3741。**未列举的标签默认透传子节点**（`figure/dl/thead/iframe/svg/select` 等）。

`StripControlChars` 3754：逐字符丢弃 `<0x20`（保留 `\n \t \r`）、`0x7F`、`0x80–0x9F`（C1，含 CSI `0x9B`）→ ESC 与 8-bit 序列都被剥掉。
⚠️ **不剥** `U+200B`、`U+202A–202E`、`U+2066–2069` 等双向/格式字符 → **显示欺骗面未封**。

### 6.1 两条链路对照

| 维度 | `--grep` 全文 | `--search` 语义 |
|---|---|---|
| 入口 | `GrepCli` 6606（分发 3293，无长度守卫）；关键词必须 `args[0]` 6628 | `SearchCli` 6515（分发 3289 有用法守卫） |
| 参数 | `--limit`(20,≥1) · `--max-snippets`(10) · `--context`(50,≥0) · `--feed`(显示号→`GetRealId`) · `--full` · `--json` | `--feed` · `--threshold`（默认 `cfg.Embedding.SearchThreshold`）· `--json`；**无 `--limit`** |

| 数据源 | FTS5 虚表 `ItemsFts`(trigram) 4224，rowid = `Items.Id` | `Models(IsCurrent)` + `Vectors` + `fulltext/vecs.json` + `VectorsChunks` |
| 排序 | FTS 靠 rowid(=Id) 升序（**刻意不 ORDER BY** 6841）；LIKE `ORDER BY i.Id` 6881；SQL LIMIT | `OrderByDescending(Score).Take(20)` 7021（**硬编码 20**） |

### 6.2 `--grep` 决策

- `FtsSuitable` 6811：取**最长连续 `char.IsLetterOrDigit` 段**（CJK 算字母），**≥3 走 FTS**，否则 LIKE。按段而非整串长度，偏保守——`"熊猫"`、`"C++"` 走 LIKE。
- `TryGrepFts` 6825：`FROM ItemsFts fts JOIN Items i ON i.Id = fts.rowid JOIN Feeds f … WHERE ItemsFts MATCH @m AND i.Status='active' [AND i.FeedId=@fid] LIMIT @limit`；`@m` = 加引号的短语（内部引号翻倍）。trigram 对任意字符建 3-gram，短语查询即子串匹配 → **中文 ≥3 字可搜，<3 字符无法匹配**。异常 → `null` 6865。
- `TryGrepLike` 6869：四列 `LIKE @kw ESCAPE '\'`（`\ % _` 转义 6885），`ORDER BY i.Id LIMIT`，**全表扫回退**。
- 片段 haystack = `Title + StripHtml(Content ?: Description) + Summary` 6675；`ExtractGrepSnippets` 6734 合并重叠窗口并统计 total。

### 6.3 `--search` 决策

- 查询向量 `SafeEmbed` 6917（null → return null，CLI **静默无输出**）；`thr = --threshold ?? config` 6915；`score < thr` 丢弃（严格小于，等值保留 6957）。
- **三路召回**：
  1. `Vectors WHERE ModelId=当前`，active/feed 过滤 6937-6946，逐行 cosine
  2. sidecar `vecs.json`：需 `smodel == modelId`、未 seen、sfeed 匹配 `--feed` 6974，命中回表 `GetSearchHitForItem` 7025（LEFT JOIN Feeds、**非 active 返回 null**）
  3. `VectorsChunks` 逐块 cosine，**先聚合每 item 最高分** 6986-7006，已存在则取更优分 7012，否则补入 7016
  - 去重 = `seen`(HashSet) + `FirstOrDefault`；Score = cosine（`CosineSimilarity` 6127，维度不等返回 0，`+1e-12` 防零除）
- **NO_INDEX 两种**：无 `IsCurrent` embedding 模型 6925；`Vectors` 与 `VectorsChunks` 均 0 行 6934。
  ⚠️ 但**查询向量在 NO_INDEX 判定之前就已产生** 6917（白耗一次 API 调用）。

### 6.4 FTS 维护契约

- 懒回填 `EnsureFtsIndexed` 4299：`MAX(Id)` vs `MAX(rowid)`（DBNull→0 4312），`ftsMax >= itemsMax` 即 return；否则 `DELETE FROM ItemsFts` + `INSERT … SELECT` 4315-4316（**无事务、无 ORDER BY**）→ 下次搜索自愈。
- 增量：`InsertNewItem` 同事务 `SyncFtsInsert` 5792（`Summary` 恒传 `""`）；删除走裸 SQL：删源 3865、按 Guid 7094；**`SyncFtsDelete` 4340 无任何调用点**。
- 主库损坏自愈 4352+ → 新库首次 grep 全量回填，索引无需显式恢复。
- sidecar：仅 `FeedHasVectors` 557/577 为真才嵌（隐含「先索引后抓全文」），`BackfillFulltextSidecars` 593 由 `--index`/`--reindex` 调 6454/6506；`EstimateTokens(StripHtml(ft)) > SizeTokens` 的超长文跳过 606（交给切块）。

### 6.5 关键不变量（可作测试断言）

1. `DoGrep` 唯一入口必先 `EnsureFtsIndexed` 6797
2. `MAX(ItemsFts.rowid) >= MAX(Items.Id)` 成立后，任何新插入必须同步写 `ItemsFts` 同 rowid
3. kw 长度 ≥3 时 FTS 命中集 == LIKE 命中集（同 status/feed 过滤）；`FtsSuitable=false` 时 FTS 结果恒空
4. `ItemsFts` 不得存在无对应 active `Items` 的 rowid（查询侧 JOIN + Status 兜底）
5. 结果 score ∈ [0,1]，itemId 唯一，条数 ≤20（`--search`）/ ≤limit（`--grep`）
6. 无当前 embedding 模型或无任何向量 ⇒ NO_INDEX 且返回 null，**不抛异常**

### 6.6 可疑点

1. **静默永久漏索引**：`SyncFtsInsert` 的 `catch{}` 4336 失败后，若之后有更大 Id 成功插入，`MAX` 校验即通过 → **该文永久搜不到**，且 `TryGrepFts` 不抛异常、不会回退 LIKE。更硬的一处：本地导入路径 1068-1083 **根本不调 `SyncFtsInsert`**（仅当该文恰为最大 Id 时靠重建补救）。
2. **删除路径三套实现行为不一**：5676（删源）不删 `ItemsFts`、不清 sidecar；1181（删导入文章）不删 FTS 行；只有 3865/7094 完整。
3. **LIKE 失败被谎报**：6908 吞异常 → null，6801 打印「请输入搜索关键词」。
4. **语义不一致**：MATCH 覆盖原始 HTML 的 `Description`/`Content`，而片段 haystack 用 `StripHtml` 6675 → 出现「count=0」提示 6718；FTS/LIKE 大小写折叠**仅 ASCII**，而匹配器用 `OrdinalIgnoreCase` 6744 → 非 ASCII 大小写（İ/Σ 等）必然「命中但 0 次」。
5. **`--full` 同样受 `--limit` 截断**；`TotalSnippets` 实为「出现次数」6681，6725 用它算「还有 N 段」会夸大。
6. **并发窗口**：`EnsureFtsIndexed` 另开连接 4303（`DoGrep` 已持 conn 6793）；`DELETE → INSERT` 非事务 4315，其他进程此刻 grep 得 **0 命中且无 LIKE 兜底**。
7. **sidecar 无原子性、无日志**：`SaveFulltextVecs` 全量覆写 520，`LoadFulltextVecs` `catch{return new()}` 516 → **文件损坏即静默丢全部向量**；每次搜索整份读入并在 C# 端暴力 cosine（无 ANN、无 SQL 下推）。
8. **过滤依据不统一**：主表 `i.FeedId` 6944 vs chunk `vc.FeedId` 6993（FeedId 漂移会漏/串）。次要：`SearchCli` 的 `--feed` 解析失败静默 6531，未知 flag 被拼进查询串 6546，错误文案在 `--json` 解析前输出会变纯文本 6535。

### 7.2 向量粒度（决定语义搜索质量）

| 存储 | 粒度 | 写入者 |
|---|---|---|
| `Vectors`（主表） | **只存标题向量** — `SafeEmbed(a.Title)` 6437/6495 | `--index` / `--reindex` |
| `fulltext/vecs.json`（sidecar） | **整篇正文**向量 | `EmbedFulltextSidecar` 553（**仅当该源已有向量**） |
| `VectorsChunks` | 分块向量 + 每块前 200 字 `Snippet` | `EmbedItemChunks` 6302 |

触发切块的条件（6326）：`StripHtml` 后 >200000 字符截断 → `EstimateTokens(plain) <= SizeTokens` **直接 return** → `chunks.Count <= 1` 也 return。

**后果**：正文在 2000 token 以下的文章，若又没抓全文缓存，**正文完全不参与语义检索**——只靠标题向量。中文文章尤其容易落进这个区间。

### 7.3 切块算法

`EstimateTokens` 6212：**仅 `U+4E00–U+9FFF` 每字计 1，其他非空白字符 ×0.3** → 假名 / 谚文 / 扩展汉字 / CJK 标点全部按 0.3 **严重低估**。
`SplitLongParagraph` 6225：`charBudget = max(200, sizeTokens*2)` **按字符硬切**（可能切裂代理对）。
`ChunkText` 6237：按 `\n\n` 分段 → 顺序累加到 `> size` 出块 → 从块尾逐段回取做重叠（`acc+t > overlapTokens` 即 break）→ **段落本身大于 overlap 时重叠为 0**。

### 7.4 索引与重索引

`IndexArticlesCli` 6381：列源 → stdin 读编号（`all` 取全部）→ `GetRealId`（**仅 Feeds 显示序号→真实 Id**）→ 选 `Status='active'` 且 `NOT EXISTS Vectors` 的文章 6419 → y/n 确认 → `EnsureModel` → 逐篇 `SafeEmbed(Title)`（**向量长度 ≠ 配置维度时改写 `cfg.Embedding.Dimensions` 并 `SaveConfig`** 6439-6444）→ `SaveVector` → `EmbedItemChunks` → 每 10 篇进度 → 两次回补 6454/6458。（`extraArgs` 为**死参**）

`ReindexCli` 6463：统计 → y/n → **同一连接、无显式事务**依次 `DELETE FROM Vectors`、`DELETE FROM VectorsChunks`、删 `vecs.json` 6477-6482 → 全量重嵌 → 回补。

**事务边界**：每个向量各自 `OpenDb` + 单条 UPSERT 自动提交（6192/6282），**无外层事务、无批量事务** → 中途崩溃留半成品，且 `Models` 已切换 → 搜索报 `NO_INDEX`。
**幂等性**靠：`UQ_Vectors_ItemModel` UPSERT · chunk 主键 UPSERT · 切块前先 `DELETE FROM VectorsChunks WHERE ItemId AND ModelId` 6336 · 回补用 `NOT EXISTS` 筛选 6364。

### 7.5 摘要

### 7.6 可疑点

1. **主表只嵌标题** + 正文仅在 >2000 token 才进 chunks → 短/中文文章正文不参与语义检索（见 7.2）

3. `EnsureModel` 插入 `Models` 时用**配置维度**（6163），实际维度只在 `IndexArticlesCli` 事后回写配置文件（6442）→ **`Models.Dimensions` 与实际向量维度永久不一致**（重跑时因 `(Provider, ModelName)` 命中而不更新）
4. **失败静默多处**：6318 / 6341 / 6347 / 607 / 568 / 589；`LoadFulltextVecs` 反序列化失败即返回空列表（516）+ `SaveFulltextVecs` 无原子写全量重写（519）→ **向量丢失或文件截断均无提示且不自动重建**
